# 游戏内 UI 排版优化工作流

适用范围：Godot 4.7、竖屏 `576×1024`，主场景 `res://scenes/Game.tscn`。

目标：逐页优化已有 UI 的尺寸、间距、对齐、信息层级和手机安全区；功能、文案含义、交互、数值、场景层级和美术风格完全不动。

## 0. 每轮输入与输出

每轮只处理一个界面，按以下顺序推进：

1. 主界面 HUD
2. 底栏 Dock
3. 任务信封弹窗 QuestPop
4. 设置弹窗 SettingsPop
5. 新手指南 GuidePop / TutorialLayer
6. 日结算 Night / SettlementCard
7. 开始菜单 StartMenuLayer
8. Toast 与临时提示

输入：当前手机网页截图、目标界面名称、一句完成标准。

输出：该界面的排版改动、前后对照截图、排版检查结果、功能回归结果。没有手机截图时，只做可撤销的小步调整，不判定定稿。

## 1. 建立基线

开始改动前记录：

- 当前分辨率：`576×1024`。
- 中文和英文各一张完整截图。
- 弹窗关闭、按钮点击、语言切换、信封开关、结算进入各操作一次。
- 当前界面涉及的节点路径和现有 z 值。
- 当前 `git diff`，避免把其他进行中的改动算进本轮。

截图统一命名：`界面-语言-before.png` 与 `界面-语言-after.png`。

## 2. 排版改动白名单

本工作流允许修改：

- `anchor_*`、`offset_*`、`position`、`size`。
- 容器的 `separation`、alignment、size flags。
- `custom_minimum_size`、内容边距、九宫格拉伸边距。
- 字号、行距、自动换行、文字对齐和截断方式。
- 图标显示尺寸、等比缩放和图文间距。
- 不改变点击区域语义的视觉留白。

原则：优先在 `.tscn` 调排版；只有现有布局本来由脚本生成时，才在对应样式函数中调整布局数值。

## 3. 功能冻结红线

本工作流禁止修改：

- 信号连接、回调目标、按钮行为、输入吞噬和约 280ms 防抖。
- `_input`、`_toggle_quest`、`Loc.toggle()` 与弹窗 Dim 的点击逻辑。
- 游戏状态、货币、股票、鸡群、教程、烤炉和结算逻辑。
- `Loc.gd` 的文案含义及语言切换逻辑。
- `WORLD_BACK` / `WORLD_FRONT` 归属。
- `_raise_hud_chrome()` / `_set_settle_chrome()` 的权威层级。
- Dock、Night、QuestPop、SettingsPop、QuestBtn、设置按钮和 Toasts 的 z 值。
- 节点名称和被脚本引用的节点路径。
- 音效与环境音开关关系。

如果为了排版看似必须触碰以上任一项，本轮暂停，单独提出原因，不把它混进 UI 排版提交。

## 4. 单界面优化循环

### A. 先看问题

只记录可观察问题：贴边、拥挤、视觉重心偏移、同级元素不齐、数字跳动、中文或英文溢出、触控区域过小。不要在这一阶段改功能或换画风。

### B. 一次只改一个变量组

按以下顺序，每次改完立即看结果：

1. 页面安全区和主容器宽高。
2. 大区块之间的间距与对齐。
3. 卡片内部边距。
4. 文字层级与换行。
5. 图标尺寸与基线。
6. 最小触控尺寸。

不要同时重排多个界面；这样才能快速定位回归来源。

### C. 双语与状态覆盖

每个界面至少覆盖：

- 中文、英文。
- 最短值与最长值，例如低金额和高金额。
- 默认态、按下态、禁用态（若原本存在）。
- 弹窗打开态。
- 与结算层同时存在时的正确可见性。

### D. 差异门禁

提交本轮前检查 diff：

- 改动应集中在目标界面的 `.tscn` 排版属性，或现有样式函数中的纯视觉数值。
- 不应新增或删除信号连接。
- 不应出现新的状态变量、计时器、输入事件、游戏数值或节点重挂父级。
- 不应夹带素材替换、文案改写或其他界面顺手调整。

触发红线时，把越界部分从本轮移除后再继续。

## 5. 自动检查与人工验收

### 项目检查

- Godot 加载场景无脚本红字。
- 运行项目已有的冒烟测试；动到教程相关界面时必须运行 `TutorialSmokeTest.tscn`。
- 确认脚本引用的节点路径仍存在。
- 对照本轮 diff，确认没有功能文件的非视觉改动。

### 手机网页检查

完成标准以 `https://chickenstock.netlify.app` 为准。导出并上传后强制刷新，再检查：

- 文字无裁切、重叠或异常换行。
- 重要按钮不贴边，单手点击不误触。
- 中英文都不撑破卡片。
- HUD、地图按钮和底栏互不遮挡。
- 弹窗打开和关闭行为与优化前一致。
- 进入结算时 Dock 隐藏，结算 CTA 不被遮挡。

### 固定功能回归

- [ ] 点信封：打开后不立刻关；结算时仍能开。
- [ ] 点语言：只切一次；按钮为 `语言：中文` / `Language: English`。
- [ ] 进结算：底栏消失，不挡报告 CTA。
- [ ] 若动了烤炉附近排版：烤到 100% 能结束并重置。
- [ ] 若动了层级或 Dock：结算层仍在底栏之上。

没有亲自在手机网页完成的项目标记为“待真机”，不能写“已通过”。

## 7. 完成定义

一个界面只有同时满足以下条件才算完成：

1. `576×1024` 手机网页上中英文均无裁切和遮挡。
2. 与基线相比，功能行为完全一致。
3. diff 只包含该界面的排版改动。
4. 固定功能回归无失败项。
5. 有 before / after 对照，并由太阳海在手机网页上确认成片。
