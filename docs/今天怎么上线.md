## 第 1 步：在 Godot 里下载网页导出模板

现在这台电脑**一个模板都没有**，所以「导出」按钮点了也出不来东西。

1. 打开 Godot 编辑器，打开这个项目
2. 顶部菜单：**编辑器 → 管理导出模板**
3. 点 **下载并安装**，版本选 `4.7.1.stable`
4. 等进度条走完

**做完应该看到什么**：管理导出模板窗口里显示「已安装 4.7.1.stable」。

> 如果下载很慢或失败，可以在同一个窗口里选「从文件安装」，
> 手动下 `Godot_v4.7.1-stable_export_templates.tpz` 再选进去。

## ~~第 2 步：注册 PostHog，拿一把钥匙~~（已完成，跳过）

「钥匙」就是一串 `phc_` 开头的字符。游戏靠它知道该把数据发给谁。

1. 打开 https://posthog.com ，注册（免费额度每月 100 万条事件，够用很久）
2. 注册时选区域：**选美国（US）**，后面填的地址要和这个对上
3. 建一个项目，名字随便，比如 `chickenstock`
4. 左下角 **Settings → Project → Project API Key**
5. 复制那串 `phc_` 开头的字符

**做完应该看到什么**：剪贴板里有一串类似 `phc_AbCdEf123...` 的字符。

> 这把钥匙是「只能写不能读」的采集钥匙，放进网页里是安全的，PostHog 就是这么设计的。
> 但**不要**去复制 Personal API Key 那一个，那个是管理钥匙，不能放网页里。

## 第 3 步：在 Godot 里导出网页版

> 如果导出按钮是灰的或者报错说缺模板，回第 1 步。

## 第 4 步：把统计文件同步进去，顺便体检

  跳过 posthog-config.js（已存在，里面可能填着线上 token）
  apiKey 已填：phc_AbCdEf12…

把那个 `index.pck = ?? MB` 的数字记下来，第 8 步要用。

> `export/web/` 这个文件夹不会进 git，所以钥匙不会被传到网上。这是故意的。

**如果它报错说 apiKey 是空的**，说明 `export/web/posthog-config.js` 被删掉了。

`apiKey` 去 PostHog 的 **Settings → Project → Project API Key** 重新复制一份。

> 钥匙只存在于 `export/web/posthog-config.js` 这一个地方，而且这个文件不进 git。

## 第 6 步：先在自己电脑上试一局

别急着传。先在本机跑起来，确认数据真的能到 PostHog。

```bash
node tools/web-serve.mjs
```

然后浏览器打开 **http://127.0.0.1:8080** 。

玩这么一局：

1. 如果弹新手教程，随便走完或跳过
2. 从菜单进「普通模式」
3. 点几下鸡收蛋、卖个蛋糕（随便玩，20 秒一天）
4. **等第一天结束，会弹出结算卡**
5. 结算卡上有个按钮写着 **「填反馈 → 重试今天」** —— 点它
6. **六题问卷弹出来了**：游戏水平、年龄、性别、玩过类似游戏吗、为什么想重试、一句建议
7. 随便选几个，点提交
8. 游戏会回到当天早晨

**做完应该看到什么**：问卷正常弹出、能选、能提交，提交后回到早晨。

## 第 7 步：去 PostHog 看数据到了没

打开 PostHog 网站，左边菜单点 **Activity**（有的版本叫 Events / Live events）。

**应该看到这些事件，按时间从下往上排**：

| 事件名 | 意思 |
| --- | --- |
| `page_open` | 页面打开了 |
| `game_ready` | 游戏加载完，能操作了 |
| `menu_view` | 看到了主菜单 |
| `play_start` | 开始玩 |
| `day_start` | 第一天开始 |
| `day_end` | 第一天结束 |
| `retry_offer_view` | 看到了「填反馈」这个按钮 |
| `retry_offer_click` | 点了它 |
| **`survey_view`** | **问卷弹出来了** |
| **`survey_submit`** | **问卷提交了** |
| `retry_restored` | 回到了当天早晨 |

**如果一条都没有**，按这个顺序查：

1. 浏览器按 F12 打开控制台，看有没有红色报错
2. 切到 Network 标签，刷新页面再玩一下，看有没有发往 `posthog.com` 的请求
3. 请求是红的（失败）→ 钥匙填错了，或者网络到不了 PostHog（见文末「大陆网络」）
4. 连请求都没有 → `analytics.js` 没进包，回第 4 步重跑一次命令

### 问卷答案在哪看

在 Activity 里点开那条 **`survey_submit`**，右边会展开一堆属性，往下翻能看到：

| 属性 | 是哪一题 |
| --- | --- |
| `self_reported_skill` | 游戏水平 |
| `age_bracket` | 年龄段 |
| `gender` | 性别 |
| `genre_experience` | 玩过类似游戏吗 |
| `retry_reason` | 为什么想重试 |
| `free_text` | 那句开放建议 |
| `answered_count` | 一共答了几题 |
| `dwell_ms` | 在问卷上停留了多久（毫秒）|

**答案存的是英文代码不是中文**（比如 `intermediate`、`18_24`），这是故意的：
换了界面语言也不会变成两套数据。对照表在 `docs/ANALYTICS.md` §5.6。

**「没答」和「不想说」是两个不同的东西**：没答这一题时属性根本不出现，
主动选了「不想说」才是 `undisclosed`。统计时别把两者混在一起。

> 等玩家多了之后，别再一条条点开看。左边 **Product analytics → New insight**，
> 选事件 `survey_submit`，Breakdown 选你想看的那一题，就能直接出分布柱状图。

## 做完之后

### 把链接分开发

`cohort` 是用来区分「朋友帮忙测」和「陌生人自己来玩」的，两批人的数据不能混着看。
发链接时按人群用不同的后缀：

| 发给谁 | 发这个链接 |
| --- | --- |
| 朋友 | `https://chickenstock.netlify.app/?c=friends` |
| 学校群 | `https://chickenstock.netlify.app/?c=school` |
| 不知道谁 | `https://chickenstock.netlify.app/` |

**链接发出去就不能改了**，改了同一批人会被拆成两组。

### 头半小时对一遍账

1. `page_open` 有数据进来吗
2. 事件的 `build` 字段是不是 `2026.09.19-pt1`（不是的话说明传的是旧包）
3. `test_env` 是不是 false（是 true 说明用错配置了）
4. `day_end` 里那堆 `day_xxx_count` 不全是 0（全 0 说明计数没接上）

## 大陆网络：一个今天可以先不管、但迟早要管的事

数据是直接发往 PostHog 的美国服务器的。你自己可能有代理所以能通，
**但你的测试玩家大概率没有**。发不出去的时候代码是**静默丢弃**的，
不报错、不重试、游戏照常玩——所以你会看到一份「少了一整批人」的数据，却完全看不出来。

**今天先不用管**，先把整条链路跑通。但等真的开始拉人测试之前，
按 `docs/LAUNCH_CHECKLIST.md` 的 §B4 加一个 Netlify 转发，让数据先发到自己的域名再转出去。

判断有没有中招的办法：让一个**没有代理**的朋友点链接玩一局，
然后去 PostHog 看有没有他那一局的数据。没有就是中招了。

## 遇到问题时按这个顺序查

| 症状 | 多半是什么原因 |
| --- | --- |
| 导出按钮点了没反应 / 说缺模板 | 第 1 步没做完 |
| 网页打开是黑屏 | 传的时候只拖了 index.html，要拖整个文件夹 |
| 手机上还是旧版本 | 没强制刷新，浏览器缓存了旧的 `index.pck` |
| PostHog 一条数据都没有 | 钥匙没填、或第 4 步的命令没跑、或网络到不了 |
| 数据有但问卷没有 | 问卷要在结算卡点「填反馈」才出现，而且提交过就不再弹（设置里有补填入口） |
| 事件里 `build` 是旧版本号 | 传的是旧包，重新导出 |
